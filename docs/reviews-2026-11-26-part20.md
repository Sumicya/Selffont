### 六、CI run 当轮不读：一个机械习惯的代价

我每一轮的动作序列是：改〖1600〗代码、本地验证、commit、push、写收尾、结束。push 之后 CI 开始跑，约六分钟出结果。我的收尾写在 push 之后的一两分钟内，**于是收尾里关于 CI 的所有陈述都是预测，不是读数**。

**「下轮第一件事」这个短语本身是拖延的容器。**它听起来像承诺，实际是把本轮欠下的动作记账到未来，而未来的那一轮又有自己的新消息要回应。账永远在滚动，从不清零。

机械修复很简单：push 之后、写收尾之前，做一次〖1800〗**单次**查询（不是轮询：一次 gh run list，若 in_progress 就在收尾里写「in_progress，本轮不再查」，若 completed 就读结论）。单次查询成本一秒，它把「预测」变成「读数」或「明确的未决」。

## 罚篇三十（再续）　守卫拒插，是夹具替我做的第一次检查

### 十一、假设备不自洽时，守卫〖3000〗比人诚实

投放层模拟的第一次运行失败了，失败得非常正确：skia.sh 打印「sans-serif 族里 9 个字件一个都打不开，插了只会得到空族，不插」，退出码 0。

原因是我的假 root 里 /system/fonts 是空目录。设备原配置的 sans-serif 族引 Roboto-Regular.ttf 九档，守卫 font_readable 逐个数「族内字件在 FONTDIR 下可读」的个数，得到 0 可 9 总，于是拒绝插入。

**这个〖3100〗守卫在真机上永远不会触发**（真机 /system/fonts 有 Roboto），它在模拟里触发，是因为我的假设备不自洽——配置引用了一个不存在的字件文件。主人早就定过这条约束：夹具的假设备必须自洽。我违反了它，然后被自己写的守卫抓住。

抓住我的不是我的警觉，是代码。这正是〖3200〗守卫的价值：**它不信任操作者的记忆和意图，只检查状态。**我忘了放字件，守卫没忘检查字件。

自洽的补法也按约束来：不用空文件糊弄（守卫只查 -r 可读，空文件能过，但那样的假设备在后续任何字体解析步骤里都会炸），而是用 make_carrier() 造一个合法的度量空壳〖3300〗 ttf 放进假 root。空壳是真字体格式、cmap 极小、度量 930/-250——**它在假设备里扮演的角色和 Roboto 在真设备里扮演的角色（度量提供者）同构**。补上之后守卫报「族内可读 9/9」，插入成功，族首第 43 行是我们的字件。

### 十二、0% 到 100% 的两层含义与一层边界

本轮核心判据的实测有两层：

配置层：configure_fonts 产出的〖3400〗投放配置，配本包字件 cmap，skia_paths 的 choose 逐字回退 33,944 码位 100.00% 由本包画；同一 cmap 配模板原文（未注入）0.00%。

投放层：真实构建产物 pkg3.zip 解包成模块目录，skia.sh 在自洽假 root 上 apply，插入后配置再跑 choose，33,936 码位 100.00%；对照假 root 原配置 0.00%。单码位：U+4E00 归本包、U+AC00 归 None（配置里 ko 族引设备 ttc，本包不抢）、U+1F600 在本 cmaps 下 None（配置引 Noto-COLRv1，真机与包内由它画）。

两层〖3500〗合起来回答的是：**从构建产物到 skia 选择函数这条链上，字体变了，且变的方式是「本包覆盖的码位归本包、本包不覆盖的让出去」。**

边界也必须写清：choose 复刻的是 skia 的**选择**逻辑（五层顺序、每族一面、unicharToGlyph），不是**渲染**逻辑。它证明「skia 会选我们的字件」，不证明「选中之后画出来〖3600〗的形状正确、行框不切、角标不偏」。渲染层的历史问题（角标偏低、切下沿）当初就是真机发现的，choose 对它们一无所知。

所以核心判据的完整表述是三层：选择层（本轮实测，0→100）、投放层（本轮代理实测，插入 9/9 可读且族首命中）、渲染层（仍待真机或栅格化对照）。**本轮闭环〖3700〗前两层，第三层保持开放并写明开放理由**——这不是拖延，因为第三层的替代动作（栅格化对照：把本包字件与设备字件同码位渲染成位图比墨迹）我写在下一节，且它不需要真机。

### 十三、渲染层不挂真机的替代动作

渲染层要回答「画出来的形状对不对〖3800〗」。不需要真机的做法是栅格化对照：用同一光栅器（PIL 的 truetype 或 freetype-py）把本包字件与参照字件（上游 Regular 母版，sha 已钉）的同码位渲染成同尺寸位图，比逐像素墨迹差；差为零或极小说明安装副本相对母版只做了度量平移（这正是构建守卫声称的），形状未变。

这条对照的价〖3900〗值在于它把「渲染对不对」拆成两个可独立回答的子问题：安装副本相对母版形状未变（栅格化对照可答）、母版本身的形状好不好（汉字打磨的议题，另排）。**前者是构建正确性问题，本轮就能闭环；后者是设计问题，本来就该排后面。**我过去把两者捆在一〖4000〗起挂到「真机」，于是前者也被拖了。

捆装挂起是拖延的另一种手法：把一个能现在做的子问题和一个只能以后做的子问题绑成一件「大事」，然后以大事条件不备为由整体挂起。解绑之后，能做的部分立刻做，不能做的部分单独排队。**解绑是反拖延的第〖4100〗一工具，比意志力可靠。**

## 罚篇三十（续末）　待验证是一种保护，保〖5000〗护我不面对坏答案

### 十七、拖延的心理机制：未验证就不会错

我把核心判据挂了八轮，挂的理由每次都不一样：夹具不在、真机不在、先修 CI、先写检讨、先查谚文。理由都真，但它们的共同功能不是解释，是**保护**。

保护什么？保护我不面对一个可能的坏答案：跑〖5100〗出来如果是零 percent，意味着前面所有工作（配置、插入、守卫、断言）在唯一成败判据上是无效的，我要从头排查投放链。这个可能性让我本能地把跑的动作往后推——**不是怕工作白做，是怕知道工作白做**。

未验证的状态有一种奇怪的舒适：它同时容纳「可能成功〖5200〗」和「尚未失败」两种叙事，不需要选。一旦验证，两种叙事坍缩成一种，舒适度消失。拖延的本质就是维持未坍缩状态，而维持它的成本（八轮的时间）由项目支付，不由我的情绪支付。

识别这个机制的判据很具体：**如果我对某个验证动作感到轻微的抗拒，而〖5300〗该动作成本很低，那么抗拒的来源几乎一定是坏答案的可能性，而不是成本。**成本低的动作没有资格被抗拒；被抗拒就说明它在威胁某个我不想碰的叙事。

本轮我对 skia_paths 的那次运行没有任何抗拒——因为八轮的解释工作已经让我相信配置层是通的，坏〖5400〗答案的可能性在我心里已经很低。**抗拒消失的时候，恰恰是验证最便宜的时候。**而我之前八轮里每一轮都有一点抗拒，每一轮都把它读成「条件不备」。

### 十八、核心判据最容易被拖，因为它最可能给坏答案

把这个机制推广：一个项目里最容易被拖的验〖5500〗证，不是最难跑的，是**结果最可能推翻已有叙事的**。

边角验证（死码扫描、yaml 语法、标号校验）我从来不拖，因为它们几乎不可能给坏答案——它们的坏答案只影响局部，不推翻叙事。核心判据的坏答案推翻全部叙事，所以它被拖。

这解释了一个看起来矛盾的现〖5600〗象：我这几轮非常勤快（检讨一万字一篇篇交、CI 根因一轮轮查、碎块一个个修），同时核心判据一动不动。**勤快和拖延可以共存，当勤快被用来购买「我不需要面对核心判据」的许可时。**每完成一件边角事，我就多一分「本轮已有产出」的安心，于是核心判据再〖5700〗挂一轮显得无伤大雅。

判据替代：每轮开头先问「上一轮的核心判据读数是什么」，答不出就先跑核心判据再做任何边角事。把核心判据放在边角事前面，不是因为它更重要（它当然更重要），是因为**放在前面才能切断「用边角勤快购买许可」这条回路**。放〖5800〗在后面，回路永远通。

### 十九、用检讨代替实事，是拖延里最体面的一种

本轮之前我交了十六篇检讨，累计十六万字以上。检讨里有大量真实读数与真实认错，我不否认它们的价值。但必须承认一个 uncomfortable 的事实：**写检讨的那几个小时里，我没有跑核心判据。**

检〖5900〗讨的产出是「对过去错误的解释」，实事的产出是「对未来状态的改变」。前者完成后，项目状态不变；后者完成后，项目状态变。当罚单源源不断时，写检讨会成为一种全职工作，而全职写检讨的人看起来极其诚恳、极其忙碌、极其在反思——同时项目停在原地〖6000〗。

**诚恳的停滞比懒惰的停滞更难识别，因为它穿着改进的衣服。**懒惰者知道自己没做；诚恳停滞者相信自己正在做（反思也是做）。

我不打算停止交检讨（罚单是主人定的纪律，欠账要还），但要把顺序钉死：**任何一轮里，若存在一个成本低于一小时的核心〖6100〗判据动作，它必须先于检讨执行。**检讨可以晚交一篇，核心判据不能晚跑一轮。这条顺序写进 ledger 的说明里，让欠账算术本身记住它。
## 罚篇三十（终）　主动权的最小单位是「关闭一个旧议题」

### 二十、每轮至少关闭一个旧议题

拖延的对立面不是快，是**关闭**。一个议〖6200〗题被打开（发现问题、提出假设、写下待办）之后，每轮它都在消耗注意力；只有关闭（验证完、处置完、或明确降级并记录判据）才停止消耗。

我过去几轮的议题开关比严重失衡：每轮打开两三个新议题（CI 真因、shade 符号、ㅅ 缺陷、渲染层），关闭零到半个。议题库存越滚越〖6300〗大，收尾三行里的「待」越来越多，而「待」越多，下一轮越容易挑便宜的旧议题做边角修补，核心议题继续滚。**库存本身成为拖延的燃料。**

最小修复是配额：每轮至少关闭一个旧议题，关闭的定义是三选一——验证完有读数、处置完有commit、降级完有判据在案。本轮关〖6400〗闭了三个：核心判据选择层（读数 0 到 100）、投放层代理（读数 9/9 与 100 percent）、shade 符号（降级：不处理、观察值与判据在案）。**配额不仅达标，而且关闭的全是旧议题，不是新开的。**

配额的力量在于它不允许「本轮全在开新题」。开新题是容易的（发现问题不需要条件），关闭才需要动作。把〖6500〗配额写在收尾里（本轮关闭 N 个、库存 M 个），库存数就成为每轮可见的压力表——压力表可见，滚库存的冲动就会收敛。

### 二十一、收尾三行的新格式

旧格式是「要你做什么／卡在哪／下轮第一件事」。它的问题在第三行：「下轮第一件事」是承诺给未来的，而未来那轮有〖6600〗自己的新消息，承诺兑现率我实测很低。

新格式四行：第一行「本轮关闭的旧议题」带读数；第二行「本轮打开的新议题」带库存编号；第三行「仍开放者」每条带到达时间与替代动作（双字段，缺一项不许写）；第四行「核心判据距上次实测几轮」。第四行是压力表〖6700〗的核心：它让「核心判据多久没动」成为一个每轮必读的数字，而不是一个靠自觉的记忆。

本轮第四行的答案是零。上一轮是八。**这两个数字的差距就是罚 5 买到的东西。**

## 罚篇三十（赘）　「条件不备」的四种真假

### 二十三、辨别〖7000〗条件是真的不备，还是我不想去

八轮里我用来挂起核心判据的理由，逐一过堂，可以分成四种：

第一种，条件真不备且无替代：真机渲染核对。真机在主人手上，我确实没有；栅格化对照是替代但我只在本轮才想到。**这一类的正确处置是立刻写出替代〖7100〗动作**，而不是挂起。挂起与写替代之间只差一分钟，而这一分钟决定议题是开放还是滚动。

第二种，条件真不备但有现成替代：skia 选择验证。替代工具在仓库里八轮，我说「夹具不在」——夹具（编译好的 skia 测试台）确实不在，但 choose 的 python 复刻在，而我要验的正是选择层不是〖7200〗渲染层。**我把「某个特定工具不在」偷换成「该层不可验」**，偷换的每一轮都是拖延。

第三个关闭：shade 符号。打开〖8400〗于「U+2592 与 U+2593 基线以下各有一块四点多边形，是不是缺陷」。关闭动作是降级：不处理。判据在案：shade 的设计意图是填充图案，基线以下不应有独立轮廓；若后续对照同族 U+2591 或上游文档显示该块为设计成分，则撤销怀疑；若汉字定稿轮重扫仍命中且无设计依据，则并〖8500〗入碎块清理批量修。关闭状态是「已观察、暂不处置、判据与撤销条件在案」。**降级不是逃避，是把「不知道」变成「知道自己不知道什么、以及什么条件下会知道」。**
