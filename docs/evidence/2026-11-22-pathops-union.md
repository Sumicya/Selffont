# pathops 整字并集实验 2026-11-22（代码已实现，默认关闭）

## 做了什么
`tools/design_cjk.py` 新增 `_union_rings()`：把「每笔一环」的轮廓用 **pathops 布尔并集**
合成整字轮廓，与上游 Zen Maru `build.py` 的 `removeOverlaps=True, overlapsBackend="pathops"`
同一机制，也是 `docs/design-principles.md:13`「合并笔画要用保留曲线的布尔运算」的要求。

开关 `SELFFONT_UNION_STROKES`，默认 `0`（关）。

## 为什么默认关闭：三档拓扑不一致
pathops 直接吃二次贝塞尔，曲线保留，合并本身工作正常。环数也对：

| 字 | 并集后环数 |
|---|---|
| 長 | 1 |
| 永 | 3 |
| 醫 | 10 |
| 鬱 | 11 |

但 `cjk_vf.build_vf` 直接抛错：

```
U+4FEB 三档轮廓点数不一致，无法做可变：{300: [631,297,76,68], 400: [615,281,76,68], 500: [654,283,68]}
U+002B 三档轮廓点数不一致，无法做可变：{300: [128,128], 400: [178], 500: [128,128]}
```

原因：三档笔画粗细不同（300 = 0.60×、400 = 1.00×、500 = 1.45× 母版），**并集拓扑随粗细变**。
500 档笔画粗，两个笔画并成一个环；300 档笔画细，还是两个环。

「只在 400 档求并集、300/500 保持每笔一环」也试了，同样炸——400 档环数与另两档不匹配，
`gvar` 的点对不上。

**这是可变字体的硬约束，不是参数问题。**

## 当前基线（40 字抽样，seed 11，300 px，±6 px 对齐）
| 项 | 值 |
|---|---|
| 中位 | 0.916 |
| p10 | 0.885 |
| 最低 | 0.874 |
| ≥0.93 | 6/40 |

## 要用并集的前提
放弃可变字体（`SelfroundsCJK-VF`），改出**三份静态实例**（300/400/500 各一份 TTF）。
那时每档独立求并集，拓扑不一致就不是问题。

代价：
- 体积 ×3（现在是 1 个 VF 文件顶三档）
- `supportedAxes` 那条字件没了，Android 15+ 运行时实例化的优势没了
- `font_fallback.xml` 要从 1 条改成 3 条按 weight 列出
- `cjk_vf.py` 的整套 gvar 逻辑用不上

这是产品级决定，不在本轮擅自做。

## 未验证
并集在**单档**（比如只出 400 静态）上的 IoU 收益还没量——因为构建管线现在是 VF 专属，
要量必须先有一个单档出件路径。下一轮若确定走静态三份，第一步就是量这个。
