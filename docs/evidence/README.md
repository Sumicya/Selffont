# 验证证据

写「已验证」之前先答一句：证据在哪个文件。答不上来就只能写「推断」或「未验证」。

## 三层，各自留各自的证据

| 层 | 断言的样子 | 证据形式 | 存放 |
| --- | --- | --- | --- |
| 配置层 | 设备上的配置内容符合构建预期、模块挂上了 | 命令输出存成 `.txt` | 本目录 |
| 构建层 | 打包器行为、断言有效、产物命名 | `build.py --check` 与 CI 运行记录 | 更新日志里写明 run 号 |
| 渲染层 | 屏幕上的字形、版面、字重 | **截图 `.png`** | 本目录 |

三层的结论不许合并成一句「真机验证通过」。配置层核对过不等于渲染层看过——`grep -c` 数的是配置文件里的字符串，一个像素都不证明。「看起来没问题」也不算验证，要么是坐标/半径的具体数字，要么是能复现的脚本输出。

命名：`<日期>-<项>.png`，例如 `2026-10-07-系统字形.png`。

### 7. "了"横折转角跟竖笔死角硬接（2026-10-16～17，多轮迭代，当前为续十一「真单曲线」版，仍待主人确认）

背景：横折转角（contour2，一条独立弧线轮廓）跟竖笔主干（contour0）在顶部
衔接点坐标重合，但衔接之后 contour0 自己先走一小段**水平直线**（到竖笔右上角），
再急转 90° 走**垂直直线**往下——两个转折挤在很短距离里，是视觉上"死角"
"机械感"的根源。这条问题改了很多版，中间版本（对称弓形、纯直线竖笔等）
都被主人否决或自己验证出新问题，具体过程见 git log（`tools/le_slant.py`
的提交历史），这里不重复贴中间版本的图，只记录当前这一版在做什么、
验证到什么程度、还有什么没解决。

**转角去尖角**（这部分已经稳定、没有争议）：把顶边的"水平直线→90°角→垂直
直线"换成 `vf_round.py` 同款的拐角削圆公式（圆弧控制点取原拐角顶点，两端
锚点各退/进半径 r），半径取整条水平边的全长，把整条顶边吃进弧线，衔接点
直接平滑弯下去。

**竖笔+钩尾连续大弯弧**（当前这版在试的结构，主人明确要求"按筑紫那种
整条腿连续甩出去、钩尾位置跟着偏移"的结构重做，并知情接受这是风险更高的
改动）：

1. 竖笔左右两条边分别换成**单调**（不是鼓一下再弓回原位，是从顶部到底部
   单方向往左漂移）的 TrueType 三控制点二次 B 样条，两端切线严格贴合原来
   直线段的方向（跟上面的转角圆弧、下面的钩尾都不会有折角）。
2. 在竖笔左右两边"双方都存在"的公共高度区间内，两边用同一条漂移曲线
   （只是左右各自的起始 x 不同），保证任意高度上两边间距（笔画粗细）
   精确不变。

### 8. "七"/"九"顶端横折弯鼓成球形端头（2026-10-15，已修复）

背景：横折弯（或横折弯钩）顶端是一条独立轮廓的平头收尾，跟另一条横画十字交叉而成，本应看起来像"横捺"收束的转折，但通用的"自由端头"规则把它当成孤立端头处理，削成了突出的半圆球形鼓包。这个模式在"电/也/七/了/元/围/己/已/九/乙/园"等很多字上都有端头，但只有"七"（contour1 点16/17）和"九"（contour2 点15/16）这两处——顶端完全外露、单独一条竖钩跟横画交叉而不是互相包住——鼓包在视觉上明显突出，所占比例远超其他同类端头。

修法：复用第 5 项已有的 `skip_caps` / `force_corners` 管线，把这两处端头的点坐标加进 `skip_caps` JSON（跟 `foot_trim.py` 产出的结构完全一样），让 `vf_round.py` 的 `detect()` 跳过"判成端头"，改走拐角圆化路径——不用新写分类逻辑。

- `2026-10-15-qi-jiu-cap-bulge-fix-3weight.png` —— "七"/"九"二字，Light/Regular/Heavy 三档对比，顶端从鼓球形端头变成跟其余拐角一致的适度圆角。
- 回归：改动后 20 字×3 字重拓扑一致性检查全部 OK（见第 9 项）。
