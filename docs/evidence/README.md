# 验证证据

写「已验证」之前先答一句：证据在哪个文件。答不上来就只能写「推断」或「未验证」。

## 三层，各自留各自的证据

| 层 | 断言的样子 | 证据形式 | 存放 |
| --- | --- | --- | --- |
| 配置层 | 设备上的配置内容符合构建预期、模块挂上了 | 命令输出存成 `.txt` | 本目录 |
| 构建层 | 打包器行为、断言有效、产物命名 | `build.py --check` 与 CI 运行记录 | 更新日志里写明 run 号 |
| 渲染层 | 屏幕上的字形、版面、字重 | **截图 `.png`** | 本目录 |

三层的结论不许合并成一句「真机验证通过」。配置层核对过不等于渲染层看过——`grep -c` 数的是配置文件里的字符串，一个像素都不证明。

命名：`<日期>-<项>.png`，例如 `2026-10-07-系统字形.png`。

## 取证（设备上跑，一条一张）

```sh
# ① 系统正文：一段中文，看字形是不是圆的
su -c 'screencap -p /data/local/tmp/sf-1.png'
# ② 角标数字：状态栏 / 通知角标，看数字有没有偏低或切下沿（度量归一的效果）
su -c 'screencap -p /data/local/tmp/sf-2.png'
# ③ 等宽：终端或代码类 App 里对齐的英文，应当是 Droid Sans Mono，不该是圆体
su -c 'screencap -p /data/local/tmp/sf-3.png'
# ④ 生僻字：随便一段带生僻字的文本，看清掉 MiSans 后是否仍渲染成圆体
su -c 'screencap -p /data/local/tmp/sf-4.png'
# 拉进仓库（Termux 里，仓库默认在 ~/Selffont）
for i in 1 2 3 4; do cp "/data/local/tmp/sf-$i.png" ~/Selffont/docs/evidence/ 2>/dev/null; done
ls -l ~/Selffont/docs/evidence/
```

## 沙箱里做不到的部分

打包器的沙箱取不到主字体（`release-assets.githubusercontent.com` 握手即断），所以字形渲染图无法在沙箱里生成，只能来自设备。能取到的只有仓库里那份字体配置模板（`fonts.xml`，193 个家族），基于它出的图属于配置层的可视化，不能当渲染层证据用。
