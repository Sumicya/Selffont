# 设计原则

- 2026-10-22｜关键词：自动改形过度、笔画简化观感丑｜自动几何候选只用于定位；没有明确的目标字形与预期视觉、且未经同基准正常字号和局部放大核对前，不把算法候选直接当成设计结果或批量改字。
- 2026-10-22｜关键词：圆头不是平头、去钩继续做｜钩尾处理必须形成圆弧收头而不是平切；先把改动限制在已指定钩尾，局部放大核对端点衔接后再考虑扩大范围。
- 2026-10-22｜关键词：V3 丑、完整字形上下文｜端头局部几何干净不等于整体好看；收到明确负面观感时，将该版标作不接受，继续优化，并同时核对完整字形、同基准对照与端头细节。无自交或构建通过不得替代视觉验收。
- 2026-10-23｜关键词：粗细统一、授权字体参照、鸟/也分别对应、非临摹、圆头、电不加粗｜主人明确草图分别是“鸟”“也”，只能提炼各自整体造型思路，不描笔画、不混淆字符；全样本笔画粗细须在图上可见地统一，可借有许可的字体研究重量原则但不复制轮廓；钩尾用半圆收头，己/已末笔适度延长；电的中间田框收窄须围绕中线且恢复共同笔宽，不能加粗隔断，advance 与可见墨迹边界分别报告，不把几何量化当作审美通过。
- 2026-10-24｜关键词：当前图唯一明确、Maruko 自制 KR、区分笔宽处理与曲线精简｜审阅入口只突出一张标明日期和范围的当前主图；KR 不因上游无字重就直接止步于系统回退，先用 Maruko 自有 Jamo 做可逆 Hangul 原型；曲线控制点减少须如实称曲线精简，不冒充可见笔画简化；笔宽实验只按已确认范围实施，且不得擅自删减汉字语义笔画。
- 2026-10-24｜关键词：无钩别把点剪掉、笔画不许缩、要平滑、旧图清掉｜去钩只能去掉卷回去的那一小截、不许把笔画剪短（钩收到"看着是直的"就停）；不能把「点」「撇」这类独立短笔画当成钩；去钩后切口必须圆头收笔。以字根稿（214 部首）为审阅单位逐字看平滑度，不拿指标代替观感。主人本轮选的取向：钩只收到看着是直的就停（不切到钩根），因为切根会让竖弯钩短掉 2–3 倍笔宽。
- 2026-10-24｜关键词：上游的折也要修、磨平不缩笔画、直角不许圆｜放大后能看见的折角就是缺陷，"上游本来就有"不能当理由；修法只替换区段中间点、保留两端点与端点切向，所以笔长、交点都不动；磨完必须回头核对直角与锐角字（丁卜刀力弓乙乃匚山小）没有被圆化，且这一步要跑在曲线精简之前——它输出的是折线。
- 2026-10-24｜关键词：放大看端头、接头要相切、别拿指标当验收｜主人放大核图后看到的"边缘一波一波"和"端头不圆"必须当真：先分清是上游自带还是流水线引入，再动手；曲线精简的验收不能只看 IoU 与点数，还要看相邻段的切线是否连续（只连续不相切的二次曲线串在放大后必然呈多边形），以及端头半圆在 6000 px/em 下是否仍是圆。
- 2026-10-24｜关键词：先查根因再调参、曲线必须是曲线｜"边缘一波一波/端头不圆"这类问题要先查输出里到底有没有曲线段，再谈容差；曲线精简的验收必须报「线:弧」段数与单段最大转角，全是直线的输出无论 IoU 多高都是多边形字体。端头按真半圆做，单段圆弧转角不超过 90°（单段近似 180° 的径向误差 10.8%，两段 90° 降到 6.07%）；判自交必须按真实曲线取样，只查控制点会漏。
- 2026-10-24｜关键词：别把曲线展平再拟合、点数要跟原版比｜重描成折线再"精简"只会得到更差的折线：原版 `龍` 210 点含 58 段真曲线，我们"精简"后 276 点 0 段曲线。判断精简好不好，先跟原版的点数与曲线段数比，再看逐处放大的边缘；不能只看 IoU。
- 2026-10-24｜关键词：读原生、别重描｜上游描摹字体本身已经是干净曲线（`龍` 210 点含 58 段弧），任何"光栅化再描线"的中间步骤都会把它降级成折线；合并笔画要用保留曲线的布尔运算（pathops），不要重新采样。判断是否有必要做某一步，先量它改变了多少字形（214 部首里需要并集的只有 0 个）。
- 2026-10-25｜关键词：提炼设计思想、别在原设计上叠东西、横截面、标准半圆、等宽笔画｜主人两次要「提炼设计思想」，并明确「基本属于二创字了就不要在本来就不完美的原设计上加还没修平滑的东西」。据此定量读出 Maruko 的三条规则（86 字样本）：① **等宽笔画**——骨架半笔宽中位 31.1、四分位 30.5–32.0，字内离散度 IQR/r 中位 0.073；② **端头 = 半径等于半笔宽的标准半圆**——398 个自由端头的横向射线 d_min/r 中位 1.01、10 分位 1.00；③ **字形由骨架定形，笔画沿骨架等宽展开**。收笔必须按这三条**重新生成**，不能拿一个正圆去封原轮廓上斜切的刀口：切口法向若取骨架局部切向的垂线，在弯段上不等于横截面法向（`九` 差约 25°），弦被拉长到 1.11×2r → 端头宽 11% = 脓包；圆盘又有一半悬在笔画外（`也` 只剩 22.5% 是墨）= 缺口。正确判据是一条几何事实：**横截面 = 过骨架点、两端等距、弦长恰为 2×局部半笔宽的那条线**。用它重切后，六个字的弦/2r 全部 1.000、接缝角 0.3–17.5°、半圆盘内墨迹 99.8–100%。
- 2026-10-25｜关键词：别用光栅重描、保留原生曲线｜按骨架**栅格重画**（膨胀 + find_contours + approximate_polygon）虽然能把钩整条去掉，但会把细笔画抹平（`必` 的心、`包` 的内框、`電` 的雨丢失，IoU 0.79–0.93）。这与 2026-10-24「读原生、别重描」是同一条：轮廓上的操作必须保留原生曲线，重描只能当诊断图，不能当交付。
- 2026-10-25｜关键词：速度、平滑、乙未切、包横折钩、VF 未考虑｜实测四字重（Light 150 点 / Regular 80 / Medium 86）拓扑一致但点数完全不同，**同一字形在三个字重下不能共用一套切口**，收缩包围盒、切点位置都得各自跑；这是本轮之前没考虑实现的。速度上把逐度射线求交换成「按弧长细分轮廓 + KD 树查等距点对」，19 秒跑完八字（原 85 秒）。切点必须从**笔尖**量起：`hook_erase` 报的钩根常常落在骨架交叉点上（`乙` 两处钩根的骨架度数都是 2/3），从钩根往里切会顺着钩走、或被交叉点挡死；改成「骨架度数 1 且离钩骨架 6 单位内」找真笔尖后，八字全部切到。切点顺序必须按**采样索引**判（S→E 顺轮廓方向指向要删的小块），用密集点索引会切掉整条轮廓（`必` 包围盒跳 675）。
- 2026-10-25｜关键词：没切、自进化｜**结论必须能被自己的度量证伪**。上一版拿「`process` 返回 ok」+ IoU 当证据，宣称八字钩全部去掉；固定框差分显示八个字只动了端头一千来个像素，`find_hooks` 重检原版 10 处、切后仍是 10 处。IoU 对占字面 1% 的缺陷不敏感，不能当验收。判据要在**同一坐标系、同一缩放**下量，且要能通过「原版 vs 原版」的对照（应当全不通过）。三条判据里前两条被自己的数据否掉：骨架转角 45°（`包` 的撇端天生 55.9°、`九` 的真钩 26.6°）、钩尖附近墨量（标准半圆端头本来就有墨，切完反而涨）。可用的只有「钩走廊内、新端头之外的墨迹占比」。
- 2026-10-25｜关键词：只留横竖斜、不要残余｜去钩的正确几何是「过钩根、法线为**钩在根处走向**的半平面直切 + 钩侧半边圆盘」，圆盘半径 = 笔身半宽。三条被否的写法：① `圆盘 ∩ 原字` 会把钩的墨加回来；② 胶囊擦钩会在与笔身相切处把笔身切成两片薄刃；③ 端头圆心不限半径搜索会跑到别的笔画的交叉口。判据要能同时管住「钩没了」和「端头不多长东西」：半宽变化 ≤1.5 px、墨量 0～−12%、轮廓块数不增。
- 2026-10-27｜关键词：放弃去钩、转向扩字集、别自己加折｜二创的钩照母版原样保留，不再做去钩/改捺（去钩要逐字判钩根加白名单，扩不动字集，而且连续四轮返工）；把力气放在扩字集与修真正的取笔根因上。横折类笔画不许自行改形（不许保留折、也不许擅自加折），母版怎么写就怎么取。
- 2026-10-27｜关键词：扩字集、先定判据、阈值抓不到的要靠眼睛｜这一轮把二创从 147 字扩到 329 字，**一条形状规则都没改**，只扩数据，说明「取笔」这层已经稳到可以批量跑：判据先写死（码位在母版 cmap 里 → IoU ≥0.93 且墨量比 0.92–1.07 → 逐字过图），再跑候选，能一次收 182 字。反过来，`够` 判据 0.94 却被眼睛否掉（交角处一块箭头形尖刺），证明**阈值管得住整体、管不住局部**：整笔丢失、尖刺、折角这三类必须看图，不能只看分数。
- 2026-10-27｜关键词：半宽实测的边界、密排字偏细｜逐字量半宽在密排字上会量错：`霜` 量到 24.5、`雷` 26.8，而简单字是 33。原因是骨架点的距离变换最大值被**相邻笔画之间的空隙**截断，量到的是空隙内切半径，不是笔宽。表现就是 `霜/露/雾/霞/零` 一族整齐卡在 0.89–0.90、墨量比却接近 1.0（形状对、整体细一圈）。这类字先不收，等半宽改成「同类字共享的笔宽先验 + 逐字只做小范围修正」再回来。

- 2026-10-27｜关键词：全 CJK、进生产、单独成族｜二创从「设计样本」变成**生产字件**：`tools/design_cjk.bin` 存笔画中线与逐笔半宽，构建时按固定拓扑描边、编成可变字体（2026-10-28 起名 `SelfroundsCJK-VF.ttf`），在 `font_fallback.xml` 里**单独一个 `<family>`** 排在主字体之前。单独成族不是风格问题：同族混 `supportedAxes` 可变字体与静态字体会让 ColorOS 16 卡第一屏（2026-10-07 真机结论），所以宁可多一个族，也不塞进现有的族。字件归入 OFL 修改作品，改名 `Selfrounds CJK`（2026-10-28 定名）、许可证随包。
- 2026-10-27｜关键词：栅格倍率与图阈值必须联动｜`_graph()` 的邻居半径写死 0.75 只在 SS=2 成立：SS=1.5 时对角邻居距离 0.943 连不上，骨架退化成 4 连通、笔画断成一截一截，墨量比掉到 0.19。改成 `1.5/SS`（对角距离的 1.06 倍）后，SS=1 与 SS=2 的 IoU 只差 0.005（0.9337 / 0.9390），速度却快一倍多——全字库两万字就是「75 分钟」和「40 分钟」的差别。凡是写死像素阈值的参数，都要标出它依赖哪个倍率。
- 2026-10-28｜关键词：自己做字就别跟母版比、好看规范｜判据与母版**脱钩**。母版只提供两样原料：笔画中线和笔宽；它自己的轮廓数、面积比、包围盒不再是验收标尺（2026-10-27 那四条「面积比 / 轮廓数与母版一致 / 不越母版框」全部作废，主人原话「都自己做字了还考虑和母版的关系干什么 好看规范就行了」）。现行硬判据只有三条，都跟母版无关：轮廓不自交、不越字身框（−40…1040 × −160…900）、笔画半宽落在 0.02–0.09 em。局部缺陷（尖刺、折角、丢整笔）仍然只能靠放大图，抽样的规矩见下一条。
- 2026-10-27｜关键词：静态多档、同族成对｜主字体从「一个可变字体」扩到「一组静态字件」时，两条硬约束：① 同一族里必须**成对完整出现**（400/500 一起），少一档会让系统把剩下的那档当成唯一档，粗体直接掉回 Regular；② `nameID 16/17`（typographic family/style）必须写，只写 legacy `nameID 1` 会让 Medium 变成另一个家族，Gecko 按家族名找字时就只剩 Regular。凡是要被家族名匹配的东西，都得把两套命名模型一起写。
- 2026-10-28｜关键词：逐笔半宽、不许整字一个宽度｜同一字里每一笔按自己的横截面量半宽，不许整字共用一个数。实测「永」28.6/28.9/30.3/30.4/31.2、「国」28.3～32.0（最粗/最细 1.13）：共用一个数会把笔画粗细压平，观感是「发灰、没精神」。逐笔半宽属于「好看」的一部分，不是可省的优化项。
- 2026-10-28｜关键词：可变字体、点数必须一致｜三档字重做成一份可变字体（wght 300–500，默认 400）时，**同一字形在三档下的轮廓点数必须逐一相同**，否则 gvar 无法插值。`pathops` 描边出来的点数随粗细变（实测 88~90、116~117），所以可变路线必须改用固定拓扑描边：中线等参数采样、沿法向偏移 ±半宽、两端补固定段数半圆。构建期逐字断言点数一致，不一致直接失败，不许「差不多」混过去。
- 2026-10-28｜关键词：自制渲染器不算验收｜用 PIL 多边形自绘的对照图只能当草稿：它按奇偶规则填充，会把 nonzero 下本来实心的交叉口画成白洞，害得人去修一个不存在的缝。验收一律走**真实字体文件 + FreeType**（`PIL.ImageFont.truetype` 直接读生成的 otf/ttf），并且母版与自研必须用同一字号、同一基线坐标渲染。
- 2026-10-28｜关键词：让、多出来的小点、碎墨｜母版里汉字自带的孤立碎墨按**脏污**处理，不进字库：判据是「汉字 + 与所有中线都不相交 + 长边 < 0.10 em」。语料依据：母版自己的点（`.` `·` `:` `：`）实测直径 111～120（/1000 em），而 `让` 左下角那团只有 78×69，且同族字 `认·说·话·语·讠` 都没有。**非汉字一律不动**——`Ǡ` `Ȧ` 头上那种 0.087 em 的重音点是真的点，尺子量不出真假就不下手。
- 2026-10-28｜关键词：Skia 读哪份配置、只插不换｜Android 框架读 `font_fallback.xml`/`fonts_base.xml`/`fonts_ule.xml`，而 Flutter、WebView、厂商小组件走 Skia，Skia 把路径写死成 `/system/etc/fonts.xml`（`SkFontMgr_android_parser.cpp` 第 31/777 行）；只换框架那几份时这些程序一个字都不变（真机实测：Selffont 在该文件里出现 0 次，另三份各 16 次）。这一份**只插不换**：往里加我们的字件行，OEM 字件（OPPO Sans 等）一行都不许删——整份替换会把它们全删掉，天气小组件就掉回 OPPO Sans。
- 2026-10-28｜关键词：行框锚定设备空壳、不是「和某个字体一致」｜行框（hhea 与 OS/2 typo）的锚点是**基础包里的度量空壳**——那是设备上真正决定行距的东西，属于设备事实；不是任何一款字体的偏好值。「做和主字体一样的重校准」指的是走同一套**流程**（同一个函数、同一个空壳、同一套切墨判据），不是把数字做成和谁一样。验收只报自身判据：hhea/typo 等于空壳、usWin 盖住本字库墨迹包络、逐字最坏值；**不许**再把「与文渊差多少」「中位比 1.00x」写进结论，那是拿别人的字体当自己的尺。
- 2026-10-28｜关键词：字宽自算、空白补字形｜字宽是排版节奏，属于设计的一部分，不许整表搬运外部数值。规则：全角类（CJK、全角标点、全角形式）固定一个 em；半角类按本字实际墨宽加两侧 0.06 em 侧距；无墨的空白字符取四分之一 em。实测 `一` 1000、`a` 582、`A` 724、`1` 343、空格 250（外部表是 535/653/383，不同才是自算）。另外母版里没有轮廓的空白码位（空格 / 不断行空格 / 全角空格 …）必须补成零画笔的空字形，否则字件缺码位、系统逐字回退，空格宽度换家、行宽与断行位置全变。
- 2026-10-28｜关键词：零长度笔有两种、别一刀切｜骨架在交叉处留的零长度笔和母版的**字点**（`.` `·` `：` `…`）在数据里长得一模一样。上一版把零长度笔一律不画，`日`/`暑` 的字腔回来了，但 `：` `…` 整个码位被抹空——一刀切不成立。判据必须看**它是不是独立存在的墨**：点落在别的笔画中线一个半宽以内 = 交叉口（不画，画出来就是交叉口上一个半径 30 的圆盘，正好把字腔填死）；离所有中线都远 = 独立墨团（按半宽画正多边形圆）。这条判据还要**只看 400 档**：三档拓扑必须逐一相同，U+1E43 就是 300 档半宽小一点、被判成「不画」，三档点数对不上，整个构建炸在 gvar 前。
