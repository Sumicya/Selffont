## 当时记录的对比结论（文字留档）

1. **笔画粗细跨笔画不统一**（对应 `docs/decisions-笔画简化.md` 问题1，目前没有工具解决）：
   筑紫的“包”里，撇笔、横笔、竖钩、内部“巳”部件的横竖笔，粗细几乎完全一致，像同一根软管
   弯出来的。我们的“包”（文渊原始设计）撇笔明显比横笔细、内部“巳”部件的笔画又是第三种
   粗细——Heavy 字重下这个差距依然非常明显，不是字重不够粗的问题，是文渊黑体本身按“不同
   笔形各自补偿视觉重量”的传统黑体设计思路画的，不同笔画本来就不是同一个粗细。本仓库现有
   五个工具里只有 `dian_box_compress.py` 处理过“电”一个字的箱体墙厚问题，没有通用的
   “跨笔画粗细归一”能力。
2. **笔画交汇处（不同笔画相交，不是同一笔画自己转弯）缺少圆角**（对应问题4）：筑紫在撇笔
   接横笔的地方是一条连续弯曲的曲线，我们这里是一个没有削圆的尖角/直接相交。
   `vf_round.py::detect_corners()` 的拐角识别和合并逻辑只处理“同一条轮廓自己转弯”的凸角，
   没有处理“两条不同笔画相交留下的接缝”这一类。
3. **钩笔处理方向可能跟筑紫不一致**：当时的“包”字对照显示筑紫的钩尾保留钩形、整体软化变圆，
   不是直接切掉；`hook_cut.py` 的做法是切掉钩尖并换成圆弧端头。这一差异需要结合当前设计方向
   判断，不将这份历史对比自动当作本轮结论。

## 结论：这不是“选哪个底字体”能解决的问题

这三处差距（跨笔画粗细不统一、笔画交汇处无倒角、钩笔处理方向）被当时记录为结构性能力缺口，
不是文渊/马路口哪个底字体的问题——马路口（Maruko Gothic）大概率也是传统黑体笔画粗细补偿思路
（当时尚未实测验证），换底字体不会自动解决这些差距。真正要补上需要新增处理能力（笔画宽度归一化、
笔画交汇处倒角识别），工作量更大，本质接近“按骨架重新画轮廓”。该段仅保留当时的研究结论；
不覆盖后续筑紫 A D/400 的当前设计范围或用户确认的视觉方向。
