# Maruko 可变字体候选 V1：三档静态字重重拓扑后的插值原型

**这是研究候选，不是生产字体，没有审美验收，没有真机验证。** 图三张：现状总览 [`maruko-vf-v1-state.png`](maruko-vf-v1-state.png)（**先看这张**）、插值扫视 [`maruko-vf-candidate-v1-sweep.png`](maruko-vf-candidate-v1-sweep.png)、分段密度对照 [`maruko-vf-v1-seg-compare.png`](maruko-vf-v1-seg-compare.png)。

## 做了什么

Maruko Gothic 上游只发**静态字重**（SC 有 Light 300 / Regular 400 / Medium 500，另有 JP Bold/Black 但 SC/TC 无对应文件），没有任何设计源文件（glyphs / designspace / UFO 全没有，仓库只有 TTF 与 woff2）。要让它在 Android 上走本仓库既定的「可变字体 + `supportedAxes`」路线，只能自己把三档静态字重合成一份 VF。

`tools/maruko_vf_build.py` 的做法：把每个字形在三个字重里分别画成稠密折线 → 轮廓一一配对 → 每条轮廓取统一弧长分段数、统一起点、统一绕行方向 → 每段用一段二次贝塞尔表达 → `fontTools.varLib.build` 合成 `wght 300–500` 的 VF。

## 限制：为什么必须先重拓扑

上游三档字重不是同一套轮廓的插值结果，而是各自描摹/生成的独立字形。实测：

| 指标 | 数值 | 范围 |
|---|---|---|
| 三档共有码位 | 31,943 | Light/Regular/Medium cmap 交集 |
| 三档点数/轮廓数**不一致**的字形 | 31,551 | 98.77%，即**只有 392 个字形**结构天然一致 |
| 175 字样本里轮廓数不一致 | 67 | 38.3%（`暖` 8/8/6、`文` 3/3/2、`日` 3/4/3） |

`varLib` 要求同名字形点数、轮廓数、点序一一对应，直接喂静态字重会报 `different number of points`。所以 VF 路线的**唯一**实现方式是几何重拓扑，代价就是下面这些实测数字。

## 实测结果（175 字样本，Regular 作基准）

| 指标 | 数值 | 说明 |
|---|---|---|
| 重拓扑成功 | 105 / 175 | 175 = 175 字样本里去重后的可用字符；失败 65、跳过 5 |
| 失败原因 | 轮廓数在字重间不对等 | 缺一条轮廓就得补退化轮廓，细节会被压没再长出来，故丢弃 |
| 主字重保真 IoU（300 px/em 渲染） | Light 0.916 / Regular 0.936 / Medium 0.956（最低 0.72） | 与上游同名静态字重逐像素比 |
| 插值面积单调 | 105 / 105 | wght 300→350→400→450→500 墨迹面积单调递增（容差 2%） |
| 对齐残差 RMS | 平均 23.1 FU，p95 36.3 FU，最大 79.0 FU | 同一条轮廓在不同字重间的等弧长采样偏差 |

`wght 400` 的 VF 实例并不等于上游 Regular：基准字重也经过了重参数化，IoU 0.936 就是它的偏离量（Regular 与 Medium 保真度高于 Light，因为 Light 是结构差异最大的一档）。

## 图上能看到的真实问题（不掩饰）

扫视图里 `国/回/电/了/乙/也/田/永` 在 300 与 500 两端基本干净，中间档位仍有肉眼可见的插值瑕疵：`永` 右上笔画在 350/450 有折线感，`田` 中间的横在 350 有轻微起伏，`了` 顶部钩角在 350 略糊。这些是重拓扑把"每个字各自的最优曲线"换成"三档共用一套分段"带来的，不是渲染噪声。**不能据此说 VF 已经可用**。

## 笔画/曲线精简能做到什么（实测）

VF 里所有字重共用同一套分段，所以"简化"只能作为**统一的分段密度**施加，不能逐字随意改。`--seg-len` 就是这个旋钮，46 个可用字形实测：

| 段长 | 平均点数/字 | 总点数 | 对源 Regular 的平均 IoU | 最差字形（IoU） |
|---|---:|---:|---:|---|
| 28 | 472 | 21,702 | 0.946 | 八 0.760、包 0.827、鱼 0.890 |
| 60 | 223 | 10,246 | 0.920 | 八 0.786、入 0.813、包 0.833、已 0.837、龙 0.845 |

即"点数减半"这条真正做到了（2.1×），代价是平均保真从 0.946 掉到 0.920，`入`/`已`/`龙`/`永` 这类带长弧或钩的字掉得最明显（0.98 → 0.85 量级）。对照图是同一批字在 wght 300/400/500 下的左右并排，能直接看出右列（seg 60）在钩尾和长弧处更"多边形化"。

**这不是"语义笔画简化"**：笔画的增减、合并、结构重排一件都没做，`decisions-笔画简化.md` 里那条"只能为解决具体工程问题才动笔画结构"的限制仍然生效。

## 决策输入 1：静态单字重 vs 可变字体（按主人给定规则实测）

主人规则：「如果单字重和 VF 一样大（打包后的模块）就用单字重；VF 实在做不了也用」。

| 方案 | 105 字样本体积 | 可用字形 | 上游保真 | 字重范围 |
|---|---:|---|---|---|
| **静态单字重（Regular）** | **335 KiB** | 105 / 105 | 100%（未改动） | 仅 400 |
| 静态三档 | 997 KiB | 105 / 105 | 100% | 300 / 400 / 500 |
| 可变字体（本候选） | 357 KiB | 105 / 175（丢 40%） | IoU 0.916–0.956 | 300–500 连续 |

单字重 335 KiB 与 VF 357 KiB **基本一样大**（差 6%），而 VF 还必须丢掉 40% 的字形、并让每字偏离上游 4–8%。**按主人给的规则，结论是取静态单字重。** VF 不是"做不了"，是"做出来代价对不上收益"。

## 决策输入 2：全字符覆盖现状（主人第 0 条）

[覆盖对比图](coverage-vs-wenyuan.png)

| | 文渊圆体 VF（现生产） | Maruko SC Regular |
|---|---:|---:|
| BMP 统一表意 | 20,992 / 20,992 | 20,977 / 20,992 |
| 扩展 A | 6,592 / 6,592 | 6,582 / 6,592 |
| CJK 合计（含 B–H） | 30,665 / 97,600 | 30,338 / 97,600 |
| GB2312 6,763 字 | 100% | 100% |
| GB18030 BMP 20,992 字 | 100% | 99.93%（缺 15 字） |

- **BMP 与 GB2312 都不是瓶颈**：两款都基本完整。Maruko 唯一缺的 15 字是 `U+9FF0…U+9FFF`（Unicode 15.1 新增的扩展 I 区）。
- **真正的全字符缺口是扩展 B–H**：两款都只覆盖 31%，其中 **66,204 个 CJK 码位两款都没有（67.8%）**。换字体解决不了这件事——需要引入第三份有扩展 B–H 覆盖的源字体，这是新的重大取舍，不是本轮能定的。

## 复现

```sh
python3 tools/maruko_vf_build.py \
  --light Light.ttf --regular Regular.ttf --medium Medium.ttf \
  --chars "$(cat sample-chars.txt)" --out /tmp/maruko-vf/proto.ttf --seg-len 28
```

`--out` 旁边会写 `<out>.report.tsv`（逐字 ok / padded / missing 状态）和三份重拓扑后的主字重 TTF。字体二进制不入库。
