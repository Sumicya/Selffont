# 十点检讨：筑紫 B 字重误判、A 回退与证据责任

**检讨对象：**上一轮提交 `2aad419` 及其后续纠正。旧版十点复盘主要检查“有没有图片”，没有触及更严重的根因——把一个被用户指出字重不符的 B 候选继续当作有效参照。这份检讨取代旧版，不复用旧结论。

## 规范文件查证边界

用户提到的 `selfs/GLOBAL.md` 在当前工作树、`HEAD`、`main`、GitHub 当前分支/主分支文件查询、GitHub 按路径提交查询和代码搜索中都没有找到；仓库 `TODO.md` 只有历史文字引用。因此我**不能声称已重读这份不存在于当前仓库的文件**，也没有自行补造其内容。本轮实际重新核对了可访问的 `docs/evidence/README.md`、`docs/round-preview/README.md`、`docs/decisions-笔画简化.md` 和 `TODO.md`：图必须是真实 PNG、指向具体证据；样本范围不能冒充全字库；笔画简化须对应明确问题，不能把控制点压缩混称为结构简化。

## 十点

1. **我把仓库名当成了字体身份认证。** `TsukuBRdGothic-Std` 这个名字和 README 中的字重标签只能说明发布者怎样命名文件，不足以证明文件就是用户要的筑紫 B 版本；我当时没有先完成字体来源与目标样张的匹配。
2. **我把 `usWeightClass` 当成视觉字重证据。** 300/400/500 的元数据不等于“包”字与目标样张处在相同光学重量。用户直接指出“包”的重量不符后，这条候选资格就应立即撤销，不能靠数值标签辩护。
3. **我在关键字没有过关时，仍写下“已找到 B、无需回退 A”。** 这与用户给出的条件相反：只有字重合适、来源可用的 B 才能阻止回退。正确结论应是“B 未确认；先继续查；若无可信来源就用 A”。
4. **我把错误候选扩成了 63 项 × 三档图并提交。** 图真实渲染了那三份 TTF，却不能因此成为有效 B 证据；范围做得越大，只会让错误参照显得越像正式结论。该图现在已从当前树删除，相关文案明确作废。
5. **我没有把“官方产品存在”和“可取得/可使用文件”分开。** Fontworks 官方页面能证明筑紫 B 产品存在，但不能替代本地字体文件、适用字重核验或再分发授权。未获许可的商业源不能被我说成已取得。
6. **我在 A 回退上也必须说清具体文件，而不是说“筑紫 A 五字重”。** 本轮实际选用的是一个 `FOT-TsukuARdGothic Std D` 静态 D 文件，`usWeightClass=400`、无 `fvar`；社区 README 提到系列有五字重，不代表这一个 TTF 就有五档。该文件只提供单一 D 字重，不能满足 Light/Regular/Medium 与三档拓扑验收。
7. **我曾把轮廓曲线简化、中轴重描和语义笔画简化混为一谈。** 仓库 `curve_simplify.py` 主要减少曲线/控制点；中心线重建是栅格轮廓重描。两者都不能自动代替 `docs/decisions-笔画简化.md` 所定义的端头、突出、圆头与交汇问题。新对照只称为“钩尾简化预览”，没有夸成全套笔画方案。
8. **我没有先验证现有简化工具是否适配 A。** 把全字体 `hook_cut.py` 直接跑到 A 上，会在 33,543 个字形中检出 135,689 处钩；抽查时 `森、文、雪、道` 出现明显破坏。该全字体结果已丢弃。对 `foot_trim.py` 的 A D 目标字检查也没有发现越出，不应为了让图看起来“有改动”而捏造修复。
9. **本轮简化范围必须限定在可解释、已检查的局部。** 只对 A D 样本里检测出的 7 个唯一字形、8 处钩（“包”两处；“乙”没有候选）生成临时预览；字重没有变化，62 个唯一字的单轮廓自交检查通过。这个检查不等于视觉/语义批准，也没有扩展到其它字或全字库。
10. **我以前把交付状态写得比证据实际覆盖更完整。** 这次把候选删除、A 来源/哈希/元数据写明、63 项对照 PNG 链回文档、放大差异图另列、十点复盘改正；但仍明确标注缺少可信的 A 多字重来源、没有三档拓扑结论、不改生产字体。以后视觉交付的门槛是“来源可信且字重匹配 → 图像逐项检查 → 明确范围/缺口 → 链接并推送”，不能用提交或打开文件替代字体核验。
