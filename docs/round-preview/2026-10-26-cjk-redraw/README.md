# 2026-10-26~27 二创汉字与它为什么被删掉

这一页记录一轮已经结束的工作：按母版 Maruko 的骨架重新生成 CJK 汉字字体（下称「二创」）。
**结论写在最前面：二创已经整条下线**，模块直接分发母版本体。下面全部数字都是它在位时的实测，
留着是为了让「为什么不用」这件事可复核，而不是为了留一个能用的东西。

## 一、最终决定与判据

| | 二创（自绘） | 母版本体 |
| --- | --- | --- |
| CJK 基本区覆盖 | 19,352 / 20,977（92.3%） | 20,977 / 20,977 |
| 体积 | 40.6 MiB 字体 + 13.7 MB 中线数据 | 20.1 MiB（Regular） |
| 额外机制 | `pathops` 描边 115 秒、独立 `<family>`、单字重 | 无 |
| 与母版形状差异 | IoU 中位 0.948 | — |

判据是这一句：**自绘唯一的立足点是「另一副设计」，而 IoU 0.948 说明它不是另一副设计**。
四条数放一起，自绘只剩成本、缺口和复杂度，于是删掉。

## 二、二创当时的做法（留档）

1. 栅格化母版字形（`SS=1`，字腔留空）→ 距离变换 → 中轴骨架；
2. 度数 ≥3 的像素先摘掉，剩下的连通分量天然是「臂」；方向相反的臂接回成一条穿过去的笔画；
3. 交叉点圆心补半径 = 半宽的圆盘（T 字路口靠它成圆弧）；
4. 锐角处切段，中线用平滑 B 样条拟合（残差 ≤1 单位/点），每段 4 个控制点就是三次贝塞尔控制点；
5. 逐字量半宽，轮廓 = 中线按 2×半宽描边、圆端头 + 圆转角；
6. 收字走四条结构闸门：面积比 0.85–1.15、轮廓数与母版相等、包围盒不越出 40 单位、笔画数非 0。

笔画**照母版原样取**（2026-10-27 主人判「放弃去钩转向扩字集」）：去钩要逐字判钩根、还要配白名单，
每加一个字都要人工裁决，扩不动字集；而母版的钩只是端点一小段回卷，圆头描边照原样就是它的写法。

绿 = 进了二创字体，橙 = 被闸门剔除（1,625 字，回退母版），灰 = 母版本身也没有这个字。

## 四、过程中修掉的两个真问题（仍然成立）

1. **栅格倍率与图阈值必须联动**。`_graph()` 的邻居半径曾写死 0.75，只在 `SS=2` 成立：
   `SS=1.5` 时对角邻居距离 0.943 连不上，骨架退化成 4 连通、笔画断成一截一截，墨量比掉到 0.19。
   改成 `1.5/SS` 后 `SS=1` 可用，与 `SS=2` 的 IoU 只差 0.005，取笔速度快一倍多。
2. **每个字重开一次字体**。`rasterize()` 原来每次 `TTFont(...)` 解全表、并栅格化整个字框，
   两万字就是半小时白烧；改成进程内缓存字体 + 只栅格化字形包围盒，单字 0.99 s → 0.26 s。

这两条与自绘无关，是量字形本身的方法，`tools/maruko_skeleton.py` 因此留在仓库里。

## 五、现在模块里是什么

主字体是母版 Maruko Gothic `CJK SC` 的两档静态字件（Regular 400 / Medium 500），钉在固定提交
`97e9dd4` 的不可变 blob 上并校验 SHA-256，安装副本只动三处：行度量归一、剪空壳映射、家族名改
`Selffont SC`。**两档静态的装机表现尚未验证**（真机只验证过可变字体那一版）。
