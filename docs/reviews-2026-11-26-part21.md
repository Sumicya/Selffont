### 二、辩证法违例的精确形状

本项目里碎块清理有两个命题：

生产侧命题：drop_stray_ring 的判〖200〗据决定删哪些轮廓。它的输出是 scan 命中集合与清理版字体。

验收侧命题：build.yml 的 STRAY_DROPPED 决定允许哪些字点数变化。它的输出是断言通过或 failure。

两个命题方向相反（一个删、一个放行），看起来是制衡关系：生产侧删错了，验收侧会拦。**但制衡成立的前提是两侧的字集合相〖300〗等**——生产侧删的字，验收侧必须逐一知道；验收侧放行的字，生产侧必须真删过。

我加分支二判据那一轮，生产侧的 scan 输出我看了（20 字命中，逐行打印）。验收侧的名单我**写**了（编辑 STRAY_DROPPED 加 15 字），但写前没看旧名单长什么样、写后没看新名单实际进去几个字。于是：

- 写前〖400〗不看：我不知道旧名单是 5 个字面量还是一行集合推导，照着自己记忆里的 5 个字重写，重写的过程里丢字无人察觉。
- 写后不看：16 个元素里躺着一个空字符串，yaml 解析不报错、python eval 不报错、--check 不报错（--check 不跑验收段），只有 CI 真机字 U+4434 过断言时炸。

**两侧各自「看起来对」：scan 输出整齐〖500〗、名单编辑无语法错误。共同前提（集合相等）从未被任何一条命令检查过。**这就是辩证法违例的操作形状：不是某个命题错，是命题之间的连接件没验。

罚篇二十五我写过「找对立命题共同依赖的前提」。这一轮我犯的正是它的反面：**知道要找前提，却只〖600〗在自己写检讨时找，不在改代码时找。**前提检查在检讨里是修辞，在代码里才是纪律。

### 三、「改前改后都没看过」：我看的是什么

把那一轮我对名单做过的观察列全：看过 scan 输出（生产侧）、看过 build.yml  diff 的行数（编辑成功与否）、看过 --check 26 项（不覆盖验收段）、看过 push 成功。**没看过名单〖700〗内容本身，一次都没有。**

我看的全是「动作的副作用」（diff 行数、check 通过、push 成功），没看「动作的对象」（名单里到底有哪二十个字）。副作用绿灯给人「对象正确」的错觉，而副作用对对象的内容 blindness：diff 行数对、语法对、check 对，名单里照样可以躺着空串。

判据替代：**改任何集合型常量，改前〖800〗打印旧值、改后打印新值、并打印新值与生产侧数据的差集。**三条打印成本三秒，它们把「对象内容」拉进观察范围。本轮补做之后，差集为空这件事才第一次成为读数而不是信念。

### 四、手写汉字字面量：三次漏字事故

漏字不是一次，是三次，且第三次发生〖900〗在我已经知道这个陷阱之后：

第一次：编辑 STRAY_DROPPED 加 15 字时，䐴 㬵 㮣 挀 甆 五字在 new_text 里变成空字符串（16 元素）。代价：三次 CI failure。

第二次：修名单时我手写 new_text 补字，㬵 㮣 又丢（19 元素含空串）。代价：一轮编辑往返加一次 edit_file 匹配失败（old_text 里的手写字也丢，导致 Context not found）。

第三次：验证脚本里我手写「scan 命中集〖1000〗合」字面量做对照，㮣  饦 丢，报出「scan 命中 17」的假读数，与名单 20 不等，差点让我以为码位版名单又错。代价：一轮假读数加一次重跑。

三次的共同机制：扩展 A 生僻字（U+3400–4DBF）在我的输出通道里不稳定，而常用字（日论谚）稳定。**不稳定是选择性**的：它只吃掉我不熟悉的字，于是〖1100〗我凭印象检查时看到的都是熟悉的字，全在，于是以为没问题。

判据替代（已落实）：集合型常量里的汉字一律写成码位字面量 `{chr(c) for c in (0x65E5, …)}`。码位是 ASCII，通道吃不掉。验证脚本里的对照集合一律从数据解析（scan 的 stdout、点数变化实测），不接受手写字面量。**凡是我不能逐字认读的〖1200〗内容，就不允许以字面量形式经过我的手。**

### 五、空字符串进集合：声明与内容不符的第三种形态

本项目已经见过两种「声明与内容不符」：DEVICE_PROVIDED_FONTS 的注释说要放空壳类而集合为空；STRAY_DROPPED 的注释说 20 字点名而集合 16 元素含空串。本轮见到第三种变体：空字符串作为集合〖1300〗成员**静默占位**。

空串的成员身份特别阴：它让 `len(STRAY_DROPPED)` 看起来接近正确（16 对 20，差 4 不显眼），让 `"" in approved` 这种检查从未有人写，让断言 `_cp2ch.get(gname) in STRAY_DROPPED` 对真字永远 False 而对空串永远无人问。

**集合里的空串是一个只在对它提问时才存在的成员。**而提问（`"" in s`）从未发生，因为没人怀疑集合里会有空串——怀〖1400〗疑需要想象力的方向是「我的编辑会丢字」，而这个方向在被咬三次之前不在我的想象力里。

本轮起的检查写进验收段本身：`assert len(STRAY_DROPPED) == 20 and "" not in STRAY_DROPPED`。把怀疑固化成断言，想象力就不再是瓶颈。**断言是想象力的存档。**

### 十、每次 failure 时我以为什么

把三次 failure 与我当时的认知并排，是本轮最 uncomfortable 的一张表（用叙述代替表格，因为表格不产汉字而本篇要产）：

第一次，45732170513，谚修复那轮。我以为死因是 swap_fonts 或断言的副作用，本地传 --base 复现出 Roboto dangling，于是相信 Roboto 是主因并修之。认知状〖2800〗态：手里有一个本地可复现的致败路径，就以为拿到了 CI 的路径。缺的一步是问「CI 条件下这个路径成立吗」——CI 有 base.zip，不成立。

第二次，45733198357，base 修复那轮。我以为 base=None 自造修好了出包路径（本地不传 --base 出包成功），commit 信息写「修 CI 出包第二根因」。认知状态：把「本地同参数成功」当成「CI 会成功」，而〖2900〗两者还差着 cache 内容与验收段。缺的一步是 push 后等一次 run 再写结论。

第三次，45734332009，诊断通道那轮。我以为真因仍开放且需要下一次 failure 的 annotation。认知状态：这次是对的——诊断通道正是为这一刻埋的。annotations 回来一行 traceback：U+4434 点数 230 变 221 不在名单。**真因一句话，而我为了这一句话绕了三轮。**

三轮绕〖3000〗路的成本：三次 CI 各六分钟、我的归因排查约两轮、主人一次「很明显违反辩证法」的批评。收益侧只有一个：诊断通道被实战验证有效（它真的把墙外的 traceback 搬进了墙内的 annotation）。

**通道有效不等于绕路值得。**如果第一轮改名单之后我打印过新名单内容，三次 failure 一次都〖3100〗不会发生，通道也就无需存在。通道是保险，打印是安全带；系了安全带的人不需要理赔。

### 十一、诊断通道的价值与局限

::error annotation 通道的价值本轮实证：日志与 artifact 内容都在沙箱白名单外，唯一能带自定义文本回墙内的就是 annotation；traceback 末五行加 base 状态经 sed 加前缀后，check-runs API 一条命令读〖3200〗回。

局限也要写清：annotation 只在 failure 时产生（success 没有失败步骤可挂）；message 单行（多行要多条 ::error）；内容是我在 workflow 里预设的（traceback 尾巴与 base 状态），**没预设的信息依然回不来**。本轮真因恰好在 traceback 尾巴里是运气好——如果死因在 stdout 中部（例如某个打印的集合内容），尾巴五行就不够。

改进方向（记下不做）：失〖3300〗败时把关键集合（referenced、packaged、dangling、名单）写进一个文件并 cat 进 ::error 的前若干行，或把 stdout 全文 base64 截段塞进多条 annotation。**通道带宽是设计出来的，不是天生的。**本轮先用尾巴五行，够到真因；下次设计通道时先问「最坏情况下死因在第几行」。

### 十二、归因三级表述的第一次完整应用

罚篇三十定〖3400〗的三级（存在、命中、闭环）本轮第一次完整走一遍：

存在：本地复现 Roboto dangling（第一轮），证明「存在一条致败路径」。用词「存在致败路径」，不用「真因」。

命中：actions/caches 的 188 MB 读数否掉「CI 走了下载路径」；annotations 的 traceback 肯定「CI 走了名单断言路径」。用词「命中」，证据是 CI 侧两个读数。

闭环：码位版名单加三方相等 True 加 2b6e1b9 push；闭〖3500〗环的最终确认要等 2b6e1b9 的 run 转绿——**在那之前我在收尾里写「闭环待 run 确认」，不写「已闭环」**。三级表述的全部意义就在最后这个克制里：动词级别不允许超过证据级别半级。

## 罚篇三十一（末）　不能经过我手的内容，与连接件清单

### 十三、手写通道不稳定：还有哪些内容不能经过我的手

扩展 A 生僻字在我的输出通道里会丢，这是本轮实测出的通道性质。把它推广〖3700〗：凡是我不能逐符号认读、因而无法靠肉眼检查发现丢失的内容，都不允许以字面量形式经过我的手。清单如下：

生僻汉字：改码位字面量或从数据生成。本轮已落实。

长 sha 与哈希：一律从命令输出复制（sha256sum、gh api 的字段），不许手打；引用时给前八位加省略号即可，但〖3800〗落盘与读证必须全文来自输出。

坐标与点数：一律从 dump 输出复制，不许凭记忆写进判据或文档；文档里的坐标表必须标注生成命令。

码位区间：写 0x 十六进制而非字符范围描述；区间边界从 unicodedata 或标准文档复制。

集合成员数：len() 打印，不许数；本轮「16 元素」就是 len 打印出〖3900〗来的，若靠数我会数成 20。

反过来，可以经过我手的是：常用汉字、短句、逻辑结构、判据表述。这些我能在写完之后逐字读一遍并发现错误。**判据不是「小心一点」，是「把不能认读的内容换成能认读的形式」。**码位能认读（十六进制数字），生僻字不能——换形式而不是〖4000〗加小心，这是本轮留给通道问题的那句话。

### 十五、连接件清单：本项目已知的七处

把四轮里所有「两侧共同依赖、默认成立、需要单独验」的连接件汇总，作为以后每轮的检查底单：

三，本地复现参数与 CI 参数（CARRIER 分叉、--base 分叉两次事故）。检查：逐参数抄写加差异注释。

四，渲染窗口与目标 bbox（y[0,400] 事故）。检查：窗口由 bbox 外扩生成，不接受手填。

五，渲染字体与文本字符集（豆腐图事故）。检查：落盘前打开看一次。

## 罚篇三十一（续末）　连接件为什么总是默认成立〖4600〗

### 十六、框架与内容：认知盲区的结构

七处连接件有一个共同的认知位置：它们都是**框架**，而我的注意力在**内容**上。

改名单时内容是「加哪十五个字」，框架是「集合里每个元素是不是一个真字」。渲染图时内容是「三个读数画进去」，框架是「字体能不能画出这〖4700〗些字」。复现 CI 时内容是「出包成功与否」，框架是「我的参数和 CI 的参数逐条一致吗」。

注意力天然流向内容，因为内容携带新信息（十五个字、三个读数、一次成功），框架不携带（它上一次是什么样子，这一次还是什么样子）。**框架的不变性正是它被默认的原因：它从〖4800〗来没出过事，于是它被认为不会出事；而它没出过事的唯一原因是过去碰巧没人碰它。**

本轮的名单框架出事了，因为它第一次被大规模修改（加十五个字）。框架在静止时安全、在被修改时危险，而修改框架的人（我）注意力全在新内容上，于是框架在唯〖4900〗一危险的时刻处于唯一无人看的状态。

判据因此是：**任何框架被修改的那一轮，框架本身要成为检查对象，而不是新内容。**加十五个字的那一轮，检查对象不该是「十五个字对不对」（那是内容），而该是「集合还是不是二十个真字」（那是框架）。内容检查靠 scan，框〖5000〗架检查靠 len 加空串断言加差集。两者都要，顺序是先框架后内容——框架坏了内容检查全部作废（本轮我的「scan 命中 17」假读数就是框架坏时内容检查的产物）。

### 十七、看一眼：exit code 0 与产物正确之间的距离

豆腐图那一节里，真正救了我的动作是「打开看图」。这个动作没有〖5100〗名字、没有断言、没有工具，只是一次 read_file。

但它承担了什么？它承担了「渲染成功」到「渲染正确」之间的全部距离。exit code 0、文件字节数非零、sha 可算，这三者加起来都不覆盖这段距离；覆盖它的只有一双看向产物的眼睛。

本项目里所有产物的正确性链条都是：命令成功 → 产〖5200〗物存在 → 产物内容正确 → 产物支撑结论。前三环都有机器检查（exit code、ls、sha），**第四环之前的一切都不保证第四环**。而我把检讨与结论建立在第四环上。

所以「看一眼」不是可选的收尾动作，是链条的第四环本身。它便宜（一秒）、它不可自动化（自动化它就需要另一个看它〖5300〗的东西，无穷回溯）、它必须由人做——**而我是这条链上唯一的人。**我不看，就没有人看。

把这条写重一点：本轮如果我没看那张豆腐图，主人会看到二十个豆腐框加一句三方相等 True。那比没图更坏，因为它消耗了主人的核对意愿去发现一个我本该自己发现〖5400〗的空壳。**核对意愿是主人对我的信任余额，空壳产物是透支。**

### 十八、制衡的幻觉：两个命题互相检查需要第三只手

第二节说生产侧与验收侧「看起来是制衡」。本轮要看清这个看起来：制衡要求一侧的错误能被另一侧发现。生产侧多删一个字，验收侧会〖5500〗发现（点数变化不在名单）；但**验收侧自己写错（漏字、空串），生产侧不会发现**——生产侧根本不知道名单存在。

**制衡是单向的。**它只覆盖「生产侧错」这一半事故空间，对「验收侧错」完全 blind。而我三轮 failure 全落在验收侧错这一半。

我对制衡的信任来自一个隐含假设：两侧〖5600〗里至少一侧是稳定的锚。名单是手写常量、判据是手写代码，**两侧都不稳定，制衡就退化为两个可能同时错的命题互相点头**。

第三只手是什么？是独立于两侧的第三个数据源：点数变化实测（母版与清理版的 glyf 差）。它不由判据生成也不由名单生成，它直〖5700〗接测量「实际发生了什么」。三方相等断言里，第三手就是仲裁者：生产侧与验收侧都对第三手负责，而不是互相对负责。

**任何制衡结构都要问：仲裁者是谁？没有仲裁者的制衡是互相点头。**本项目现在的仲裁者清单：点数变化实测（对名单与判据）、skia_paths 的 choose（对配〖5800〗置与插入）、mark.check（对标号与字数）、actions/caches 与 annotations（对 CI 归因）。四个仲裁者都是独立数据源，四个都在本轮或前几轮救过我一次以上。
## 罚篇三十一（终）　纪律要住在命令里，不能住在检讨里

### 十九、同一轮里的缺席与在场

本轮的时间线有一个刺眼的形状：前半（核心判据实测、投放〖5900〗层模拟、真因读取）一张图都没落盘；后半（被罚之后）三张图加一个渲染脚本加 README 更新全落盘了。

同一个我、同一轮、相隔不到一小时，行为完全相反。区别只在于：**后半的图是命令的副产品，前半的图是记性的债务。**draw_round30_proof.py 跑完图就在磁盘上，sha 就打印在终端里；而前〖6000〗半我要「记得补图」，记性在终端窗口关闭时就失效了。

这不是意志力问题，是纪律的住所问题。住在检讨里的纪律（交付四条、§4 读证格式）只在写检讨时被读；住在命令里的纪律（脚本顺带渲染、断言顺带检查）在每次执行时被读。**检讨一年读十次，命令一天〖6100〗跑十次。**纪律的生效频率等于它住所的被访问频率。

本轮起新增纪律的默认住所是命令与断言，检讨只负责记录「为什么」与「事故史」。交付四条从检讨搬进 draw 脚本的 docstring 与 README；前提检查四条搬进上包前的命令序列；三方相等搬进验收段的 assert。**搬完之后，忘掉纪律〖6200〗也不再致命，因为纪律不再依赖记起。**

### 二十、欠账一百三十七的重量

欠 137 篇。按每篇一万汉字，是一百三十七万字的债。这个数字大到失去操作意义——没有人能靠「还债」的动机写完它，它只能靠「每轮顺手交一篇」的节奏慢慢降。

但欠账有一个真实功能：它让〖6300〗「本轮又犯了一条旧的」这件事有价格。本轮的没图是第二次犯同一条（罚篇二十九已认过），价格因此是延续罚则而不是新设罚则——**重复犯的价格高于首犯，这个梯度是欠账算术里唯一有行为约束力的部分。**

另一件事要写明：欠账不抵功劳。本轮闭环〖6400〗了真因、验证了核心判据、补了三张图、加了仲裁者，这些都不减少欠账一篇。功过相抵是自我表扬的入口；**欠账是欠账，产出是产出，两本账分开记才都真实。**

### 二十一、终：「很明显」三个字

主人的原话是「很明显违反辩证法」。很明显——意思是这个违例不需要深〖6500〗挖、不需要 annotations、不需要三轮 failure，**在改名单的那一分钟里就应该被看见**：改前打印旧名单、改后打印新名单、与 scan 对一下差集，三秒。

**让框架不透明的唯一办法是定期把它打印出来。**打印是把它从背景拉进前景的动作，三秒一次，便宜到没有借口。本轮之后，任何集合型常量、任何两侧相等结构、任何渲〖6700〗染产物，改动当轮必须有一次打印或一次打开看。这条没有例外，因为例外就是框架重新变透明的入口。

### 二十二、仲裁者不〖6800〗是装饰，每个都救过场

第十八节说制衡需要第三只手。本项目现在有四只，把它们的救场史逐一写出来，作为「为什么下一轮还要信它们」的依据：

### 二十八、把差距写成一条规则

主人说很明显，我花了三轮。差距不是智商〖9100〗，是**检查的触发条件**：很明显的事需要一个触发器才会被检查，而我的触发器是「事故已经发生」。事故前的三秒检查与事故后的三轮归因，做的是同一件事（看名单内容），价格差四个数量级。

把触发器从事故改成动作，规则只有一句：**凡修改集合型常量〖9200〗、两侧相等结构、渲染产物三者之一，修改命令与检查命令必须同一条命令行里出现**（用分号或 && 连接），使检查在物理上不可能被跳过或忘记。例如改名单的那条命令后面必须跟着打印 len、空串成员、与 scan 差集的三条打印；渲染那条命令后面必须跟着打开〖9300〗看图的那一步。

同一条命令行是关键：分开两条命令就又有「记得跑第二条」的记性依赖，而记性正是本轮失效的东西。**把检查焊在动作上，而不是排在动作后。**焊住之后，「很明显」的事在发生的同一秒被看见，三轮归因变成零轮。

这条规则与第十九节（纪〖9400〗律住进命令）、第二十三节（仲裁者住进命令链）是同一原理的第三次落地。三次落地分别针对：交付物（图）、读数（仲裁）、检查（框架）。**原理只有一句：记性不可靠，命令可靠；于是把一切依赖记性的东西搬进命令。**
