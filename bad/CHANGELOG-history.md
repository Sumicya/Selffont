## 2026-10-25 · 提炼设计规则并按横截面重切，缺口与脓包消失

- **提炼规则**（86 字样本）：等宽笔画（骨架半笔宽中位 31.1、四分位 30.5–32.0，字内 IQR/r 0.073）；端头 = 半径等于半笔宽的标准半圆（398 个自由端头 d_min/r 中位 1.01、10 分位 1.00）；字形由骨架定形。
- **切口判据换成横截面**：不再取骨架局部切向的垂线，改成「过骨架点、两端等距、弦长恰为 2×局部半笔宽的那条线」。逐点粗搜 10° + 最优附近逐度细化，取弦长误差与对称度最小、且离钩根最远的一条；补两条闸：被删必须是短弧（≤ 轮廓 1/4、≤ 12 倍半宽），包围盒收缩上限随切深放到 2.6r。
- **结果**：`九`/`乙`/`也`/`包`/`必`/`電` 六字的弦/2r 全部 **1.000**（旧版 0.89–1.12）、接缝角 **0.3–17.5°**（旧版 30–82°）、半圆盘内墨迹 **99.8–100%**（旧版 22.5–53%）。脓包与缺口在几何上不再成立。图 `hook8-crosssection.png`、`hook8-crosssection-zoom.png`。
- **`了`/`子` 仍未切**：钩根在转角上，2.2r 窗口内找不到合格横截面（`了` 1.88–2.01×、`子` 1.41–1.46×）；窗口放 4.5r 会让 `乙` 从 .989 掉到 .924，已回滚。
- **「含笔尖」判据删除**：`乙` 的 removed 两端在骨架上都是交叉点，笔尖取不到，改用「被删取短弧」——横截面把轮廓切成绕过钩尖的小块与绕整字一大圈，短的必然是钩。

## 2026-10-25 · 去钩深度诊断：切点只覆盖钩长的 42%

- 主人判「只去掉一半」。把 `hook_erase.find_hooks` 的切点和骨架实测的钩根对齐量：`九` 89.7 / 213.3、`也` 86.0 / 199.2、`包` 87.9 / 207.1、`必` 88.4 / 208.8、`電` 72.0 / 172.8 —— **覆盖 42–43%**。切点落在外扬弧中段，剩下的还弯着。
- 为什么不能直接往深切：从笔尖沿骨架走，弦长**一开始就等于笔宽**（`九` 0.5r/1.0r/2.0r 处 1.01/1.06/1.01 × 2r），弯曲率 `弧长/直线位移` 全程 1.05–1.17、骨架无分叉。这些「钩」在骨架上没有钩根，是笔画末端的连续外扬；切深了弦变宽（`九` 3.0r 1.31×、`包` 1.25r 1.51×），半圆跟着变粗。
- 试过并全部回滚：① 从笔尖走到骨架分叉（`九` 走 334 步无分叉，`電`/`包` 崩）；② 切面候选放宽到 2.6r 并奖励深度（`了`/`子`/`乙` 掉到 None）；③ 弦必须与笔身横切 ≥55°（浅站点被误杀，同样掉字）；④ 两个交点必须分列切点两侧（把 P 在轮廓外的合法切面误杀）；⑤ 修 `d` 的 y 轴翻转（骨架是像素 y 向下、轮廓是字体 y 向上，`乙` +0.0085、`包` +0.0032，但 `也` −0.021，不划算）。
- 结论：**「整钩去掉」这一版没做到**，`4cddf34` 的读数不变。下一步不能继续调 `best_cut` 的窗口，要改成按骨架重画笔端（直等宽笔身 + 半圆），而不是在弯曲的原轮廓上切一刀。
- 新增诊断图 `hook8-depth.png`（灰=原版、白=现版、红蓝点=切点两端）。工具链工作区已回滚干净，`pytest` 58 passed。
- **当天补：切点挪到钩之外**。主人圈出 `乙` 端头旁的突起锯齿。根因是切点落在离笔尖 1.05r 以内（钩本身），钩尾细条留在切口外。窗口改成 **1.2r–2.8r**，切点必须在钩之外。
- **修 `segments_of` 真 bug**：连续两个 off-curve 点的拆段里，第二段起点用了 off-curve 点本身，应是两点中点（TT 隐含点）。`乙` 的轮廓因此整条被搬走、左下角凭空多出凸起。

- **自己做字体第一版**：新增 `tools/skeleton_rebuild_prototype.py`——丢掉原轮廓、只留骨架，用整字骨架半宽中位数的圆盘膨胀，端点天然半圆、无钩尖。`九`/`乙`/`了`/`也` 接近原形，`包`/`必`/`電` 的细笔画被全局等宽吃掉（IoU 0.83–0.95）。下一步改按骨架点的**局部半宽**膨胀。图见 `skeleton-rebuild-v1.png`。
- **骨架重建 v2**：按骨架点**各自的**半宽盖盘（不再用整字中位数），并沿骨架从每个端点截掉 **2.0 倍局部半宽**再盖盘——钩是笔画末端的外扬、骨架上没有分叉，只能按长度截；截完盖盘，端头就是半径 = 半笔宽的标准半圆。补 `hmtx` lsb 同步（不补整字偏移，IoU 0.87→0.22）。IoU 0.790–0.932：钩确实整条没了、端头也标准，但栅格重描把 `必` 的心、`包` 的内框、`電` 的雨抹掉了，还不能当成品。三方对比图 `three-way.png`。
- **缺口与脓包的成因查清**：对八个字逐个切口量「接缝角 / 弦÷笔宽 / 半圆盘内墨迹占比」。接缝角 < 25° 的 `乙`/`包`/`必`/`電` 圆内墨迹 99.4–99.9%、弦/2r 0.96–1.03，没毛病；接缝角 > 30° 的 `九`(63°/38°、1.11、33.6%)、`了`(31°/31°、1.12、94.2%)、`子`(79°/82°、0.97、53.0%)、`也`(15°/63°、0.89、22.5%) 全有病。根因三条：① 切面法向取骨架**局部**切向的垂线，弯段上不等于横截面法向，弦斜穿笔画；② 半圆半径 = 弦÷2，弦一斜就比笔宽长（`九` 1.11、`了` 1.12），端头宽 11–12% = 脓包；③ 正圆扣在斜切口上，圆盘一半悬在笔画外（`也` 只有 22.5% 是墨）= 缺口。诊断图 `hook-cut-gap-blister.png`。
- **距离变换梯度当法向试过、不可行**：弦长飞到 2.6–7.4 倍笔宽。
- **切完再压「肩部」试过并回滚**：`_clamp_shoulders` 把切口两侧超出半圆的点沿半径压回，`九` .9861→.9854、`乙` .9922→.9892、`也` .9831→.9783，反而更差，且把 `也` 的捺压出缺口。放弃。

## 2026-10-05 · 真机根因定位：ColorOS 读 fonts_base.xml / fonts_ule.xml，我们只换了 font_fallback.xml

- 现象：真机（OnePlus / ColorOS，Android 16）装好后字体不变；模块目录里 `system/etc/font_fallback.xml` 字节数正常，系统侧 `/system/etc/font_fallback.xml Selffont=7`——**说明模块已正确挂载、配置已替换**，问题不在挂载。
- 根因（设备日志实证）：`logcat` 出现 `SystemFonts: Loading font config from /system_ext/etc/fonts_base.xml`。AOSP `SystemFonts.java` 是 `FONTS_XML = getFontsXmlDir() + "font_fallback.xml"`，ColorOS 把配置目录改到 `/system_ext/etc` 并改用厂商文件名 `fonts_base.xml`（另有界面实际使用的 `fonts_ule.xml`）；我们换的 `/system/etc/font_fallback.xml` 在这台机器上不被读，所以「没生效」。
- 修法：安装脚本按设备实际存在的配置逐个替换，内容永远是包里同一份新语法（`supportedAxes`）：`font_fallback*.xml`（AOSP）+ `fonts_base.xml` / `fonts_ule.xml`（ColorOS），扫描分区 `system` / `system_ext` / `product`；库存 `fonts.xml` 与 `fonts_customization.xml` 不碰。模块内容统一落 `$MODPATH/system/<分区>/etc/…`——KernelSU 的 `vendor` / `product` / `system_ext` 是指向 `system/` 下同名的符号链接，直接建顶层分区目录会顶掉符号链接（社区有卡开机案例）。
- 依据：AOSP android16-release `graphics/java/android/graphics/fonts/SystemFonts.java`（`FONTS_XML = ... font_fallback.xml`）与本机日志；ColorOS 三套配置的对应关系见 lxgw 字体模块模板的兼容性说明与 `coloros-font-switcher` v1.1.0 的说明。
- 自检：`runtime_scripts` 的假系统改成 `system/etc/font_fallback*.xml` + `system_ext/etc/fonts_base.xml` + `system_ext/etc/fonts_ule.xml`，断言替换 4 份、模块路径为 `system/etc/...` 与 `system/system_ext/etc/...`、库存 `fonts.xml` 不碰、一份都没有时中止。
- 未验证：ColorOS 的解析器是否接受带 `supportedAxes` 的新语法（其系统基于 Android 16，AOSP 解析器自 Android 15 起支持；若被拒，表现应是字体仍不生效，不会坏系统——要退就在管理器里停用模块）。装完复测方法：`grep -c Selffont /system_ext/etc/fonts_base.xml` 应非 0。

## 2026-09-30 · 火狐花体/小型大写：根因是 Unicode 逐字回退，修链对齐 fonts.xml

- 这类字符（𝓐𝓑𝓒 数学字母数字区、ᴀʙᴄ 小型大写区）不选字体，走 Gecko **逐字回退**：先按字符语言组查 `font.name-list.*`，再全清单乱序扫描，**不读 fonts.xml 顺序**——所以同一字符在系统与火狐是两副面孔。数学区语言组是 `x-math`，Gecko 在 Android 的默认名单全是设备上没有的桌面数学字体 → 直接乱序扫描。
- 修：① 配置补 `x-math` 三条（抄自 `all.js` Android 段，前置文渊）；② **构建期尾链**——把补充字库内部家族名（现场从基础包读）按 fonts.xml 顺序追加到每条 `font.name-list.*` 末尾；③ 配置拷贝在模块更新时自动刷新。自检 e2e 用真字体验尾链、`firefox_bridge` 断言 `x-math` 三条在位。**①② 至今在产线上。**
- 同一轮还把 `sans-serif-smallcaps` 纳入接管（当时判断 CarroisGothicSC 该被挤出清单）——这条 2026-10-07 按「本来是什么字体就保持什么字体」**反转**了。

## 2026-09-30 · CI 收回纯校验；模块更新自动刷新火狐配置（真 bug）

- **火狐配置陈旧坑**：`firefox.sh` 装进 `/data/local/tmp` 的是配置**拷贝**，模块更新不会自动换新——更新后没重跑 `firefox.sh`，火狐用的还是旧名单，怎么改配置都「未修复」。`customize.sh` 现在在安装/更新时检测：拷贝存在（= 已接入）就顺手刷新，不存在不碰；自检覆盖两种情形。
- **Gecko 只认字件内部家族名**（`gfxFT2FontList` 经 harfbuzz 读 name 表建清单，`AndroidFont` 包装只有 `GetFontFilePath()`），fonts.xml 别名永远进不去——这条结论后来判死了「别名字件」路线。
- CI 一度改成「直出裸 zip 挂 Release」，当天收回为纯校验（CI 不产任何东西、zip 一律本地产出）；出包重新回到 CI 是 2026-10-05 同步第二十一版之后的事。
